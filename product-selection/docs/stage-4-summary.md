# 阶段四总结：真实数据 MVP

## 这个阶段做了什么

1. 完成 `/api/search`：后端调用 Tavily，取得真实网页背景并映射为统一的搜索结果。
2. 完成 `/api/profile`：把关键词和真实引用整理成确定性的品类画像，第一版不调用 LLM。
3. 完成 `/api/listings`：通过 SerpApi 查询 Amazon 商品，处理价格清洗、去重和最多 3 个并发请求。
4. 完成 `/api/trend`：通过 SerpApi 查询 Google Trends，把周数据聚合成约 24 个月度数据。
5. 修正评分可信度：缺少月销量时不声称“没有需求”；缺少成本时不把售价空间称为毛利，并明确显示风险。
6. 修正市场与趋势逻辑：无品牌商品不再合并为同一品牌；季节高峰使用数据中的真实日历月份。
7. 第一版界面固定 Amazon 渠道，Walmart 和 TikTok 标记为进阶版，保证界面承诺与后端能力一致。
8. 排查本地代理故障：Chrome 使用 Clash 系统代理，而 Node 没有使用代理；为本地 BFF 增加代理启动配置。

## 学习者亲手完成的关键操作

- 创建并填写本地 `.env`，确认密钥不进入 Git。
- 阅读并实现第一条 Tavily `/api/search` 真实接口链路。
- 阅读 SerpApi Amazon 原始数据并完成商品映射的关键部分。
- 使用 PowerShell 直接测试后端接口并观察 HTTP 状态和 JSON 数据。
- 对市场、趋势、评分逻辑进行第一次人工 Code Review，并决定业务含义是否正确。
- 在 Chrome 分别使用 `women yoga pants` 和 `denim jacket` 完成真实 live 全链路验收。

## AI Coding 完成的机械工作

- 补齐字段清洗、去重、趋势月度聚合、错误转换和确定性品类画像。
- 编写 25 个自动化测试并修正测试与独立 Review 发现的问题。
- 修正渠道 UI、评分提示和本地代理启动配置。
- 执行类型检查、测试、构建和真实接口验证，并维护学习账本与 Review 记录。

## 最终验收结果

- 真实四接口：完成。
- Chrome 完整链路：完成，四个 Pipeline 步骤均成功并生成报告。
- 自动化测试：25 个通过。
- 类型检查与生产构建：通过。
- 密钥边界：`.env` 被 Git 忽略，前端代码和测试不包含真实 Key。

## 当前限制

- Amazon 搜索结果没有可靠的月销量字段，因此需求维度的 0 分只是缺失数据占位，不代表没有需求；总分显示为“—”。
- 当前只有售价，没有采购、物流、平台佣金和广告成本，因此不能计算真实利润。
- 第一版仅支持美国市场和 Amazon；Walmart、TikTok、LLM 与完整成本模型留到进阶版。
- 原计划写 Vitest，当前采用 Node.js 内置测试框架。它不需要新增依赖，现有 25 个测试可直接在本地和 CI 运行；这是简化实现，不影响第一版测试目标。

## 这个阶段收获了什么

- 能区分技术流程跑通与商业结论可信，两者需要分别验收。
- 第一次经历了真实接口、状态码、超时、代理、旧进程、数据缺失和 Review 的完整排错过程。
- 理解了测试负责自动验证预期，Review 负责发现需求和业务含义问题。
