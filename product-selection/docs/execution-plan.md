# 选品工作台执行计划

更新时间：2026-09-01。

本项目协作模式：**学习模式**。这是第一次 AI Coding 项目的定制选择，只对本项目有效；以后工作任务默认使用**交付模式**，由 AI 在授权范围内端到端完成。

## 以后项目计划都按这个方式写

1. 开头先用一句人话说明项目要解决什么问题。
2. 明确现在处于整个项目的哪个位置。
3. 分开记录“学习者亲手完成”和“AI完成”，不能混写。
4. 接下来只按一、二、三列出真正要做的事，并标明重要程度。
5. 工程词汇只保留面试需要掌握的，并马上用人话解释。
6. 每个任务都写清楚：为什么做、谁来做、怎样证明完成。
7. 先确定协作模式：工作任务默认由 AI 全盘交付；只有用户明确选择学习模式时才保留亲手实操。
8. 学习模式下，学习者只做关键业务规则、关键函数、关键测试和核心 Review；AI负责机械接线、重复测试、排错和交付。
9. 到学习者节点，AI必须停下，给出文件位置、简短解释、可复制内容和一条验收命令。

## 一、项目要解决什么问题

用户输入一个美国服装品类，系统收集真实数据并回答：

1. 我们要分析什么商品，去哪里找？
2. 这个商品在 Amazon、Walmart 和 TikTok 到底赚不赚钱？
3. 消费者为什么喜欢或讨厌它，评论证据在哪里？
4. 怎样避免相同查询重复花 API 费用？
5. 怎样让长任务进度由后端实时推送到页面，而不是让页面轮询？

最终生成一份带数据来源、利润、消费者痛点、可信度和风险提示的选品报告。
本项目最终范围调整为**美国市场 + Amazon/Walmart/TikTok 三个平台**。欧洲市场已由学习者明确取消，不再进入开发与验收；最终验收逐个平台诚实标明“已实现、部分实现或受接口权限阻塞”。

## 三、接下来按顺序做什么

### 1. 完成三平台数据入口与 DeepSeek 整合

重要程度：必须完成。

为什么做：让系统能取得 Amazon、Walmart 和 TikTok 商品，并根据真实公开资料生成三个平台共用的搜索词和品类画像。

DeepSeek 不是只连接 Walmart。正确数据流是：用户关键词和公开证据 → DeepSeek 生成统一品类画像与搜索词 → Amazon/Walmart/TikTok 分别搜索商品 → 各平台映射成统一商品格式 → Pipeline 生成报告。平台 API 负责“找商品”，DeepSeek 负责“理解品类、生成搜索策略和整理结论”。

第一版即使没有 DeepSeek 也能选品，因为商品搜索、趋势判断、成本利润和评分都可以由固定规则完成。DeepSeek 是增强层：减少人工整理搜索词和阅读证据的时间，并把分散资料归纳成结构化结论；模型不可用时必须回退到确定性规则，核心选品流程仍然可运行。

学习者负责：

1. Review 这条主数据流。
2. 用自己的话复述：浏览器 → BFF（前端专用后端）→ 第三方 API → 统一数据 → Pipeline → 报告。

AI负责：

1. 整合后端、前端、Prompt、Schema 和 validator。
2. 补 TikTok 商品数据适配器，并核对合法接口、权限、费用和失败方式。
3. 补渠道失败、非法模型输出和降级测试。
4. 运行全部测试、类型检查和构建。

完成证据：三个平台的状态都能在页面和报告中看见；正常路径和失败路径通过；单渠道成功仍保留结果并标为 `partial`；没有 DeepSeek Key 时明确降级，不冒充真实模型调用；TikTok 若受接口权限阻塞，必须展示真实阻塞状态，不能用假数据冒充完成。

### 2. 分别计算 Amazon、Walmart 和 TikTok 利润

重要程度：必须完成，是选品业务核心。

为什么做：Amazon、Walmart 和 TikTok 的售价、佣金和广告成本不同，不能拿同一套费率混算。

学习者本轮不参与实现；AI完成后展示核心函数、公式、固定案例和测试证据，供学习者查看。

AI负责：

1. 接好成本表单、Pipeline、评分和报告。
2. 补异常成本、空渠道和兼容性测试。

完成证据：页面分别展示三个渠道的售价、成本、单件利润和毛利率，并标明市场与币种；手算结果与程序一致。

当前执行边界：Amazon/Walmart 已有 live 商品数据；TikTok 利润只在官方接口真实返回商品售价后生成，凭据缺失时显示未授权，不生成虚假的平台利润。本轮 L2 已由学习者授权 AI 直接完成，AI在交付时展示核心函数、固定案例和测试证据。

### 3. 抓少量真实评论并标注来源

重要程度：确认要做，用来证明 AI 结论不是编造。

为什么做：报告如果说“消费者经常抱怨尺码不准”，就必须展示支持这句话的真实评论来源。

本轮只做小而真实的流程：从少量商品取得约 10 到 20 条评论，实际数量以合法接口和额度为准；归类尺码、料、面做工、舒适度等痛点，并保留渠道、商品或评论 ID、证据片段、链接和抓取时间。

学习者负责：

1. 判断一条评论为什么属于某个痛点。
2. Review 页面是否显示真实来源。
3. 检查“事实、估算、假设、缺失”标签是否诚实。

AI负责：

1. 先核对合法接口、费用、字段和失败方式。
2. 完成评论请求、映射、归类、来源展示和测试。
3. 没有合法接口或额度时立即说明，不能用 fixture 冒充真实评论。

完成证据：至少一组痛点能追溯到真实评论；无来源时程序不能生成确定性结论。

### 4. 实现缓存

重要程度：确认要做，展示工程和成本意识。

为什么做：相同关键词、市场和渠道在有效期内重复查询时，直接复用结果，不重复调用付费 API。

学习者原计划负责 Review“缓存是否命中、是否过期”的核心判断；本轮学习者明确要求 AI 完成全部实现，因此改为项目收尾时由 AI 带学习者走读，不记录为学习者亲手编码。

AI负责：

1. 完成缓存 key、TTL（有效期）、存储和接口接线。
2. 补缓存命中、过期和错误测试。
3. 说明结果来自缓存还是实时接口，以及服务重启后是否丢失。

完成证据：命中缓存时不调用第三方，过期后重新请求；两种情况都有测试。

缓存已采用带 TTL（有效期）和容量上限的服务端内存缓存：命中时跳过第三方调用，过期后重新获取；BFF 重启后缓存清空，多实例不共享。SSE 已纳入本轮：live Pipeline 移到 BFF 执行，浏览器使用 `EventSource` 接收后端步骤事件、缓存命中和终态，不做进度轮询；mock Pipeline 继续在浏览器离线运行。正式数据库仍保留在后续规划，用于长期保存多份报告、任务和证据，不是当前面试演示的验收前提。

## 五、完成标准

1. 页面能真实跑通品类、跨渠道商品、利润、评论证据和报告。
2. DeepSeek 输出经过 Prompt、JSON Schema 和 validator 三层控制。
3. Amazon/Walmart/TikTok 分别计算美国市场利润并标明币种；缺数据时诚实降级。
4. 少量真实评论能形成带来源的消费者痛点。
5. 缓存命中和过期有测试证据。
6. SSE 实时推送步骤、缓存状态和终态；断线重连、取消和结果读取有测试证据。
7. 测试、类型检查、构建、人工 Review、独立 Review、PR 和 CI 全部通过。
8. `docs/project-retrospective.md` 记录学习者实际完成、AI完成、证据和个人复述。

后续规划保留但本轮先不实现：生产数据库、分布式缓存、多实例任务持久化和生产级部署。其他非目标包括绕过权限获取 TikTok 私有数据、大规模评论抓取和真实广告投放操作；TikTok 合法商品数据入口仍受 Seller/Partner 授权阻塞。
